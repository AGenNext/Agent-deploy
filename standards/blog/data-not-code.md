# Data, Not Code

*Why we hold the line on data while the industry bets on code.*

---

Everyone is racing to make **code** the universal primitive of the agent era.
Agents that write code. Code as the interface. Code as the product. The whole
field is converging on one idea: *code-as-everything.*

We are making the opposite bet. **We hold to data.**

Here is why.

## Code can never be canonical

Code is **mutable** — it changes every commit. Code is **plural** — there are a
thousand ways to write the same thing, and no two teams write it alike. Code is
**structureless** — it carries no fixed, single meaning you can point to. And code
is **not governance** — it implements; it does not rule.

Put those together and you get the inconvenient truth: *you can never make code
canonical.* You cannot say "**this** code is the single source of truth," because
it is different tomorrow, and a hundred other versions do the same job. A
foundation that mutable and that plural cannot be the thing everyone agrees on.

## Data is real

Data is **canonical, singular, and persistent.** The entity *is* its data. The
state is data. The graph is data. When you want to know what is true *right now*,
you look at the data — not at whichever version of the code happened to run.

**Only data is real.** Everything else is computed from it.

## The contract governs; code conforms

So we keep three layers strictly apart:

- **Data** — the live entity. Real. The single ground truth.
- **Contract** (= protocol = config) — the **canonical, governing, stable** rule.
  Changed only by deliberate, quorum-approved decision.
- **Code** — the **many mutable implementations** that *conform* to the contract.

The contract is stable; code is disposable. **Many codes conform to one
contract.** Code is the worker, not the law.

## Why it matters

Code-as-everything **drifts.** It is unreliable, ungovernable, and unverifiable —
not because the engineers are careless, but because its *foundation* is mutable
and plural. You cannot govern, version, or trust a foundation that won't hold
still.

A **data-centric** system can be made canonical, governed, and verified — because
data and contracts are stable and singular. That is the entire difference between
a system you can trust and one that quietly drifts.

## The bet

Reliable, governable AI is built on **data and contracts**, not on mutable code.
Code is the conforming implementation, never the foundation.

While the industry bets on code, **we hold to data.**

*Only data is real. The contract governs. Code conforms.*
